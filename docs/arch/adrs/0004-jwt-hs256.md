# ADR 0004 — JWT HS256 sem refresh token

- Status: Aceita (será estendida pela ADR 0010, sem trocar o algoritmo)
- Data: Fase 1

## Contexto

As APIs administrativas precisam de autenticação. O `domain.md` chegou a descrever access + refresh token; o código implementou um token só.

## Decisão

JWT **HS256** (HMAC-SHA256) com `JWT_SECRET` obrigatório. Claims: `sub`, `email`, `role`, `iat`, `exp`. Expiração via `JWT_EXPIRES_IN` (local 3600s; chart de produção `1d`). Sem tabela de refresh token.

Rotas públicas: `/health`, `POST /auth/login`, `POST /users` (só `CUSTOMER`), `GET /service-orders/customer/:documentNumber`.

## Motivo

- Suficiente para demo e para o tamanho do sistema
- Sem estado de sessão no banco
- HS256 é simétrico: a mesma secret serve para API hoje e para Lambda + Gateway depois

## Consequências

- Logout é só descartar o token no cliente
- Relógio das máquinas precisa estar razoável
- `Api-Key` existe à parte para webhook/serviço interno, com comparação em tempo constante

## Alternativas

- Refresh token — mais seguro, mais superfície (tabela, rotação, endpoint)
- RS256 — melhor para Gateway nativo, exige par de chaves e JWKS
